How coding agents work, explained like you're five

Every AI coding tool has two parts. The model is the chef: the brain that decides what to cook. The harness is the kitchen: the hands, knives, fridge, fire alarm and rules around the chef. Same chef, different kitchen, very different dinner.

Model = the chefClaude, GPT, Gemini, DeepSeek, Qwen. It only thinks and talks. It can't touch anything by itself.
Harness = the kitchenClaude Code, OpenCode, Codex, Aider… It gives the chef hands (tools), a notebook (memory) and a fence (safety).
Agent = chef + kitchenDeepSeek put it as "Model + Harness = Agent". Benchmarks score the pair together, never the chef alone.

Part 1

The kitchen every agent shares

Strip away the logos and every tool below runs this same loop. They differ in how big the fence is, who rings the bell, how many helpers there are, and which chefs are allowed in.

  1. You askType a wish in a terminal, editor or app.
  2. Chef thinksThe model reads your wish plus its notebook and plans.
  3. Bell ringsBefore touching anything risky, the harness checks the rules or asks you.
  4. Hands workTools read files, edit code, run tests, inside the fence.
  5. Taste itResults (errors, test output) go back to the chef.
  6. RepeatLoop until done, then report back to you.

Part 2

Kitchen words in one line each

ToolA hand the chef can use: "read file", "run command", "search web".
SandboxA fence. The agent can play inside it but can't wreck the rest of your computer.
Permission / approvalThe bell: "May I delete this?" Some kitchens ring it every time, some never.
Sub-agentA helper chef sent off to do one job (like "find every place we use this function").
Memory fileA notebook the chef rereads every time: AGENTS.md, CLAUDE.md, GEMINI.md.
CompactionWhen the notebook gets too long, squish old pages into a short summary.
MCPA universal plug, so any harness can use outside tools (databases, Slack, browsers).
Client / serverThe kitchen runs in the back; the screen you type in is just a window. Many windows, one kitchen.
SkillA recipe card the chef pulls out only when it needs that recipe.

Part 3

Meet the kitchens

Each card has a picture to remember it by, a map of its parts, how a job runs, what it's good and bad at, and four scores out of five. The scores are this guide's judgment, comparing the tools against each other.

Also in the neighbourhood

CrushGo, by Charmbracelet. The prettiest terminal kitchen; swap chefs mid-meal. Source-available license (FSL), not fully open.
Qwen CodeAlibaba's copy of the Gemini CLI kitchen, rebuilt for Qwen chefs. Apache-2.0, has a sandbox and hooks.
Kimi Code CLIPython kitchen from Moonshot for the Kimi chef. Helpers and MCP, but no fence or hooks.
Deep Code CLISmall community kitchen tuned for DeepSeek: thinking-mode dial, skills, VS Code twin.
Roo Code, Kilo CodeCousins of Cline inside VS Code, adding "modes" (architect, coder, debugger hats).
Amp, Factory DroidClosed, paid kitchens. Amp picks the chef for you; Factory runs a team of specialist "Droids" in the cloud.

So which kitchen should I pick?

"I want the best result and will pay."

→ Claude Code or Codex CLI with their own top models.

"I want free choice of model, fully open."

→ OpenCode. Add Docker and set edit/bash to "ask" for strange repos.

"Safety matters most; let it run alone."

→ Codex CLI (real OS fence) or OpenHands (a box per job).

"I want to see and approve every change."

→ Cline in your editor, or Aider with git.

"I want to learn how agents work, or build one."

→ mini-swe-agent first, then Pi.

"I want DeepSeek end to end, cheaply."

→ DeepSeek Harness to explore; OpenCode or Codewhale for steady daily work.

"I need a fleet running jobs from Slack and GitHub."

→ OpenHands Agent Canvas or Goose.

"What about the leaked Claude Code copies?"

→ Read them to learn, don't depend on them. Legal and security risk; clean options above do the same jobs.
